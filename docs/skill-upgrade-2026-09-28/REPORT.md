# تقرير تطوير مهارات OpenCode والتحقق منها

**التاريخ:** 28 سبتمبر 2026  
**الأساس:** النسخة السابقة `opencode-maintained.zip`، مع الاحتفاظ بإصلاحاتها وتاريخ مراجعاتها.  
**الحالة:** تعديلات المصدر والأدوات المحلية واختباراتها مكتملة بالنطاق الموضح. تثبيت OpenCode الفعلي والاعتماد العام ما زالا **BLOCKED / UNCONFIGURED**.

## 1. ما تغير فعلًا

تم تعديل الملفات الأصلية في نسخة عمل، وليس في جهاز المستخدم أو إعداداته العامة.
لم تُستبدل المهارات بمهارات متوازية، ولم تُغيَّر إعدادات model/provider/MCP أو تُوسَّع
الصلاحيات. الأرشيفان الأصلي والمصان السابق لم يتغيرا.

| البند | النتيجة مقابل النسخة المصانة السابقة |
|---|---:|
| المهارات الموجودة | 43، الأسماء محفوظة |
| ملفات SKILL.md المعدلة | 12 |
| ملفات المهارات المحفوظة دون تغيير | 31 |
| تعريفات الوكلاء المحفوظة دون تغيير | 59 |
| Command wrappers | 43، تعديل واحد لـsprint-plan فقط |
| الملفات الأصلية المعدلة إجمالًا | 26 |
| ملفات التنفيذ/القواعد/المراجع/الاختبارات الجديدة | 11 |
| ملفات المصدر المحذوفة | 0 |
| مهارات أو وكلاء جدد | 0 |
| تبعيات npm أو خدمات خارجية مثبَّتة | 0 |

هذه الأعداد لا تشمل ملفات تقرير التسليم وأدلته داخل `docs/skill-upgrade-2026-09-28/`.
الـpatch المرفق مبني على `opencode-maintained.zip`، وليس على `opencode.zip` الخام.
الأرشيف الكامل يتضمن الإصلاحات السابقة مع هذا التحديث.

## 2. التعديلات والحدود

### أ. التدقيق والمقارنة

تم توسيع `.opencode/scripts/skill-audit.mjs` الموجود، بدل إنشاء أداة تدقيق منافسة.
يدعم الآن جذرًا صريحًا `--root` ومقارنة `compare` مع inventory محفوظة، لتمييز الملفات
المضافة والمحذوفة والمتغيرة والثابتة وفق SHA-256. المقارنة للبايتات فقط، وليست شهادة
تكافؤ دلالي أو توافق أو موافقة تشغيل. لا ينفّذ الأداة إصلاحًا أو اعتمادًا تلقائيًا.

أعيد استخدام التحقق من المسارات والملفات وJSON الموجود في `audit-gate.mjs`، مع استخراج
وظائف مشتركة صغيرة. القواعد الإلزامية الجديدة أُضيفت إلى بصمة الحوكمة؛ لا يُعاد اعتماد
سجل قديم لمجرد أن أسماء المهارات لم تتغير. بقي سجل الاعتماد الأصلي فارغًا وUNCONFIGURED.

### ب. الإنجاز الفعلي وGOALS / TODO

أضيفت قاعدة مركزية `.opencode/rules/task-evidence.md`، وأُدرجت مرة واحدة في التعليمات
الحالية. تربط المهمة بالهدف ومعايير القبول، التنفيذ الفعلي، الاختبارات المنفذة، نتائجها
ومراجعة الأدلة. لا يُعدّ checkbox أو commit أو خروج process برمز صفر إثباتًا كافيًا.

الأداة الجديدة الاختيارية `.opencode/scripts/work-evidence.mjs` توفر:

| العملية | السلوك الحقيقي |
|---|---|
| `check` | فحص قراءة فقط للمهام والأدلة، مع exit 2 عند DONE غير مثبت أو مدخلات غير صالحة |
| `due` | إظهار مرشحي المراجعة المتأخرة أو إعادة التحقق دون تنفيذ المهام |
| `contract` | حساب بصمة عقد المهمة والهدف ومعايير القبول |
| `mermaid` | إنتاج رسم نصي مشتق من IDs والحالات، دون renderer أو تنفيذ HTML/click |

النتائج تفصل `UNVERIFIED_DONE` و`STALE` و`EVIDENCE_VERIFIED`. النتيجة الأخيرة تعني اتساق
الأدلة المحلية المعلنة، لا البرهنة الدلالية على كفاية الاختبار أو اعتماد المهارة.
الأداة لا تعدل TODO أو تسجل موافقة ولا تمنح اعتمادًا لنفسها. يُستعمل tracker المشروع
الحالي أولًا؛ JSON اختياري كـevidence sidecar، وليس قاعدة مهام منافسة.

تُربط الأدلة بالمشروع والسياق وعقد المهمة، الملفات المعلنة قبل/بعد التنفيذ، خطة الفحص،
مصدر مولّد الأدلة، نسخة Node، سجلات الخرج والمراجعة. تغيير المدخلات المعلنة أو الهدف أو
الخطة، نقص السجلات، انتهاء مدة المراجعة، أو فشل الاختبارات يمنع ثقة DONE السابقة.
تظل التبعيات غير المعلنة وتغيّر البيئة الخارجية وكفاية الاختبار مسؤولية مراجعة صريحة.

### ج. التنفيذ وattach وانتظار الطوابير

أضيفت `.opencode/scripts/execution-queue.mjs` ومكتبتها لتنفيذ مجموعة فحوص محدودة،
في foreground وبكاتب واحد. تستخدم argv دون shell تلقائيًا، وتراقب انتهاء العملية
وتياراتها بأحداث `close` بدل sleep ثابت. تحفظ run ID، حالة كل job، stdout/stderr محدودين،
exit/signal، timestamps وبصمات الأدلة. الخيارات غير المدعومة تُرفض بدل تجاهلها.

الفشل يمنع الفحوص المعتمدة عليه. إلغاء supervisor يوقف المجموعة التابعة ويتخطى ما بقي.
انتهاء مهلة job أو تجاوز حجم الخرج ليس نجاحًا. تغيير المصدر أثناء الاختبار ينتج INVALIDATED.
مسار run يجب أن يكون جديدًا؛ إعادته تُرفض لتفادي replay غير مقصود.

`attach` هنا مراقب قراءة فقط لمسار run معروف، يعتمد إشعارات تغير الملف وانتظارًا محدودًا
0–30000 ms، ويرجع التحكم دون إلغاء العملية أو تكرارها. في Linux يتحقق من boot identity
ووقت بدء العملية لتقليل خلط PID معاد الاستخدام. فقدان الهوية ينتج LOST وليس نجاحًا.

هذا مختلف عن `opencode attach` الذي يتصل بخادم OpenCode، ومختلف عن session ID ترجعها
أداة terminal فعلية. لا توجد هنا أداة debugger أو تبنٍّ لأي PID أو daemon أو adapter
لطوابير Redis/RabbitMQ وغيرها. عند استعمال طابور خارجي، يلزم فحص in-flight/retries/
delayed/dead-letter والنتيجة المحفوظة، وليس queue depth فقط.

### د. Go / Rust / Lua / JavaScript وSemantic/Web

تم توسيع `framework-engineering` والمرجع `.opencode/docs/language-tooling.md` بدل إضافة
وكلاء مكررين. تشمل القواعد اكتشاف runtime/manifest/toolchain/lockfile الحقيقي، اختيار
الفحص الملائم، منع تنزيل dependencies أو ترقية الأدوات بلا إذن، ومراجعة حدود FFI والتزامن.

أصلح اكتشاف الملفات في `detect-gaps.sh` لإدراج Go وLua/Luau وصيغ JavaScript/TypeScript
المفقودة، مع إبقائه فحصًا إرشاديًا للمسارات التقليدية وليس اكتشافًا شاملًا. عُدِّلت
`start` كي لا تفرض محرك ألعاب أو GDD على خدمة أو CLI أو مكتبة أو مشروع ويب.

المرجع `.opencode/docs/engineering-tools.md` يميز البحث النصي عن AST/LSP/semantic
retrieval والتكافؤ السلوكي. يفرض التحقق من فهرس البحث ومراجعة المصدر الفعلي، ويحدد
الرجوع للمصادر الأولية المطابقة للنسخة عند البحث على الويب مع منع تسريب بيانات المشروع.
Semantic Web مثل RDF/JSON-LD/SPARQL مجال منفصل، ولا يفرض على مشروع بحث كود عادي.
لم يُثبَّت أو يُنشأ محرك semantic search أو LSP أو متصفح أو خدمة embeddings جديدة.

### هـ. المهام المنسية والمراجعة الدورية

أضيفت المراجعة إلى قواعد start/resume، استعادة السياق بعد compaction، انتهاء التنفيذ
المرتبط، milestones وقبل التسليم. تشمل TODO المتأخر والمعلق وDONE القديم المشكوك فيه،
مع حفظ المانع ومعرّف العملية والخطوة التالية وسبب إعادة فتح المهمة. تبقى المراجعة ضمن
النطاق الحالي؛ العثور على مهمة قديمة لا يجيز تنفيذها تلقائيًا.

**المراجعة دورية عند نقاط العمل، وليست خدمة تعمل أثناء غياب الجلسة.** لم يُثبت cron أو
scheduler أو إشعار خلفي، ولم تُوصل shell helpers بأحداث OpenCode وهمية. المؤقت الحقيقي
يتطلب تكاملًا مستقلًا مصرحًا ومدعومًا ومختبرًا.

| التحقق | النتيجة | ما لا يثبته |
|---|---|---|

| Python tests | **95 PASS، صفر failures/errors/skips** | تشمل اختبارات بنية ونصوص لا تثبت اتباع النموذج للتعليمات |

| Frontmatter | **145** ملفًا parsed، وفحص أسماء المهارات | ليس اعتمادًا دلاليًا |
| Syntax | **22** فحص Bash/Python/JavaScript نجح | ليس integration test |
| الإحالات المحلية الحرفية ضمن التغييرات | 30 مسارًا محلولًا؛ إحالة settings.json توثّق عدم وجوده | لا يغطي كل dependency ديناميكية |
| Audit registry غير المهيأ | **رفض متوقع exit 2** | ليس عطلًا يجب تجاوزه |
| Patch forward/reverse checks | نجح dry-run في الاتجاهين | لا يضمن rollback على جهاز تغيّر لاحقًا |

اختبارات Node تتضمن الـ60 السابقة و66 اختبارًا جديدًا. Python يحتفظ بالـ87 السابقة
ويضيف 8 اختبارات؛ أحدها يحتوي 10 subtests لاكتشاف الامتدادات. الإجمالي **221 اختبارًا**،
بمزيج من الاختبارات التنفيذية والبنيوية/النصية، دون احتساب Go أو syntax مرتين.

الحالات السلبية الجديدة تشمل: DONE بلا دليل، تغيير الهدف/المصدر/الخطة/السجل، دليل من
سياق آخر، أدلة مستقبلية أو قديمة، معيار قبول غير مغطى، static-only لمهمة code، فحص سلوكي
غير مربوط بالقبول، dependency cycles، paths/symlinks وJSON مكرر، رفض replay، عدم تفسير
shell metacharacters، timeout، output flooding، SIGTERM، attach محدود، وهوية PID خاطئة.
تم التحقق من CLI من خارج المشروع وجذره ومجلد فرعي باستخدام --root صريح.

تجاوز تشغيل Python الكامل سقف استدعاء الأداة، كما لم يكتمل تشغيل مجموعات متوازية كثيرة
في الاستدعاء المحدود. لم تُحسب تلك المحاولات نجاحًا. حُسبت النتيجة من **12 shard مكتملًا**،
وكل واحد من الـ95 test ID يظهر مرة واحدة فقط في التجميع النهائي. السجلات والتفاصيل موجودة
في `evidence/python-complete.json` وملفات `python-shard-*.log`.

بيئة الاختبار: Linux، Node **22.16.0**، Python **3.13.5**، Go **1.23.2**، Git **2.47.3**.
استُخدم PyYAML 6.0.3 لفحص محلي فقط، ولم يُضف كاعتماد تشغيل للحزمة. تجربة Go منعت تنزيل
toolchain/modules بواسطة `GOTOOLCHAIN=local` و`GOPROXY=off` و`GOSUMDB=off`.

## 4. ما بقي غير مثبت

| البند | الحالة والخطوة المطلوبة |
|---|---|
| OpenCode host/global installation | NOT RUN؛ البرنامج غير موجود هنا. يلزم اختبار النسخة الفعلية ومساراتها وصلاحياتها |
| Global/local skill resolution | BLOCKED؛ الـadapter السابق لا يثبت التعريف الفعلي عند التعارض. لم يُدَّع إصلاحه بهذا التحديث |
| Rust / Lua runtime checks | NOT RUN؛ cargo/rustc/lua/luac غير مثبتة أو غير متاحة في PATH |
| Mermaid rendering | NOT RENDERED؛ المخرجات النصية واختبارات IDs منفذة، mmdc غير متاح |
| Actual LSP/semantic/web tools inside OpenCode | NOT RUN؛ مراجع وقواعد انتقاء واستخدام، لا تكامل حي مثبت |
| Windows/macOS process supervision | Windows غير مدعوم في v1؛ macOS لم يُختبر هنا |
| Application/production/external queue behavior | NOT RUN؛ لا مشروع مستخدم فعلي أو نشر أو قاعدة بيانات أو طابور خارجي اختُبر |
| Timed background TODO reminders | NOT INSTALLED؛ checkpoint review فقط |
| Full domain dependency closure | غير معتمد؛ ليس كل agent/template/framework مرجعًا مُراجعًا من جديد |

راجعت هذه الجولة أجسام المهارات الـ12 المعدلة وعقودها المتأثرة والمصدر التنفيذي الجديد
والحوكمة والاختبارات المعنية. أجسام الـ31 الأخرى حُفظت وفُحصت بنيويًا، مع الاحتفاظ
بتقرير مراجعتها السابق كتاريخ، لا كاعتماد جديد. سجل مستقل لكل مهارة موجود في
`skill-review-register.json`؛ كل حالات الاستخدام تنتظر مراجعة التثبيت والـclosure المطلوب.
لا توجد مراجعة مستقلة من وكيل آخر أو إثبات بأن كل نموذج سيتبع كل تعليمة دائمًا.

الضمانات المحلية تفترض كاتبًا مخولًا واحدًا ومساحة عمل غير معادية. لا تمنع كل TOCTOU أو
تزوير الأدلة من شخص يستطيع تعديل الأدوات والسجلات معًا. صلاحيات logs ليست تنقيحًا للأسرار؛
يجب منع طباعتها أصلًا. تغيّر أداة خارجية أو متغير بيئة مؤثر يتطلب تسجيل السياق وإعادة التحقق.

## 5. الاستخدام والتراجع

افتح `engineering-tools.md` و`execution-and-queues.md` بعد مراجعة المصدر، واضبط الجذر
والـledger والخطة على المشروع الحقيقي. لا تنسخ بيانات الاختبارات أو UNCONFIGURED كأنها
موافقات. المثال داخل templates غير مهيأ عمدًا، والأدوات لا تنشئ مهام أو تتصل بخدمات تلقائيًا.

للتحقق من المصدر داخل جذر الحزمة:

```sh
node --test tests/skill-system/audit-gate.test.mjs tests/skill-system/work-evidence.test.mjs
python3 -B -m unittest discover -s tests/skill-system -p 'test_*.py' -v
node .opencode/scripts/skill-audit.mjs inventory
```

قد يحتاج تشغيل Python إلى تقسيم في بيئة ذات سقف زمني قصير؛ لا يُلغى اختبار لإرضاء السقف.
مجلد `go-smoke-fixture/` في هذا التقرير يحتوي مصدر تجربة Go، ونسخة Go محددة لتلك التجربة.

استخرج الأرشيف في مجلد جديد. راجع الـpatch والـmanifest مقابل إعداداتك قبل الدمج، ولا
تنسخ `.opencode` فوق إعداداتك العامة بالجملة. قبل التراجع، قارن التعديلات اللاحقة واستعد
فقط الملفات المتأثرة من النسخة المصانة السابقة أو اعكس التغييرات بعد فحص التعارضات.
الـdry-run العكسي نجح على نسخة العمل هنا، وليس على جهازك. لا تستعد سجلات موافقات قديمة
لتجاوز بطلان البصمات الجديدة.

## 6. ملفات الأدلة والمراجع

- `source-manifest.json`: بصمات المصادر السابقة واللاحقة والملفات الجديدة.
