# Reproduction guide

The root tests are the final regression suite. Review them, then run the commands
in REPORT.ar.md from the corrected package root. Evidence logs are actual outputs;
controlled temporary fixtures may contain intentional failure text. No live trust
records are generated by these tests.

To reproduce the original defects, use a separate copy extracted from the original
user ZIP, never a copy containing later user edits. Apply baseline-negative-tests.patch
with git apply --check first, then git apply. The patch changes only the two test
files and retains schema 1; it does not patch the original runtime. Run:

```bash
node --test --test-name-pattern='repair:' tests/skill-system/audit-gate.test.mjs
python3 -m unittest discover -s tests/skill-system -p 'test_*.py' -v -k repair
```

Expected red result: three Node test failures (stale dependency/governance and wrong
worktree) and five Python failure assertions/subtests concerning two negative test
methods (checkpoint symlink exposure and false clean Git state). The Python module
name test_repairs also matches the -k pattern, so 48 tests run, not only the new
methods. The CRLF regression is a passing preservation test, not an original defect.
These failures are historical evidence, not failures remaining in the corrected suite.
Do not copy fixture approvals into the live audit registry.
